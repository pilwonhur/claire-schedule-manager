# Claire 사용 안내 (v0.6.0)

> 구체적인 활용 시나리오 모음은 `references/usage-guide.md`에 있다. Claire 채널에서 `사용법 알려줘`라고 하면 Claire가 그 문서를 보여 준다.

모든 사용은 **Claire 전용 Discord 채널** 한 곳에서 한다. 터미널을 열 일은 없다.

## 1. 아무것도 안 해도 되는 것

- **매일 06:00 아침 브리핑**이 자동으로 온다. 06:30까지 안 오면 다음 브리핑 첫 줄에 지연 사실이 표시된다.
- 브리핑에는 새로 발견한 업무·바뀐 것, 확인 질문(`Q-0001`), 반영 상태가 실린다.
- 브리핑 바로 뒤에 **업무 현황**(0.6.0)이 온다: 오늘 일정·마감(준비 상태, 실제 겹침) → **오늘 진행 확인** → 그 외 모든 활성 업무 →
  답변 대기·보류 → **승인 대기 목록**(달력 / Tasks, 버튼) → 반영·전달 점검. 남은 업무는 마감이 없어도 **하나도 빠짐없이** 번호 버튼과 함께 온다
  ("외 N건"으로 접지 않는다. 길면 여러 메시지). 매주 반복되는 수업·회의는 시리즈마다 한 줄(다음 회차 버튼·앞으로 N회),
  한 번뿐인 일정은 모두 하나씩. 긴 목록은 다섯 줄마다 번호 버튼 한 줄.
- **진행 확인:** 교수님이 직접 등록했거나 메일로 교수님께 직접 온 요청은 **마감이 없어도 매일**, 여러 사람에게 온 공통 요청은 2영업일마다,
  전날·당일·기한 지난 일은 반드시 묻는다. 모든 줄에 답할 필요는 없다. 답이 없어도 Claire 가 완료·취소·중요도 하향을 하지 않는다.
- 보고 일부가 전송에 실패하면 그 쪽은 "보여 드린 것"으로 치지 않고 12·18시 확인 때(또는 `보고 다시`) 그 쪽만 다시 보낸다.
- **매일 12:00·18:00**(주말 포함) "아직 등록 안 된 일정·구두 약속이 있나요?"라고 묻는다. 답장으로 적으면 중복을 확인하고 등록한다.
- **완료 처리하면** 그날 Daily 노트 `## 완료한 일`에 기록된다.
- Gmail(기관 메일 포워드 포함)·Google Calendar 4개·Obsidian `#tasks`는 Claire가 알아서 읽는다. 메일을 읽음 처리하거나 옮기지 않는다.

## 2. 채널에 보내는 말

| 하고 싶은 것 | 보내는 말 | 결과 |
|---|---|---|
| 카톡·문자·다른 메일 화면을 넘기기 | **이미지만 올린다** | 요청·날짜를 읽어 항목으로 만들고 번호(`CLR-0031`)를 알려 준다. 시각이 없으면 질문을 만든다 |
| 참고 자료만 남기기 | `참고: 다음 주 학회 일정표` (+이미지) | 저장만 하고 항목·질문을 만들지 않는다 |
| 할 일·일정을 직접 등록 | `등록: 금요일 3시 김 교수 면담` / `일정: …` / `할일: …` | 질문을 최소화해 바로 등록하고 번호를 알려 준다 |
| 남은 일 전부 보기 | `전체 목록` / `할 일 전부` | 아침 업무 현황과 같은 형식으로 활성 업무 전체 |
| 오늘 남은 일 보기 | `오늘 남은 일` | 일정·마감·예정을 기준별로 보여 준다 ("데이터 기준 시각" 포함). 항목마다 번호 버튼이 붙어, 처리한 것은 버튼 → `끝냈어`로 바로 완료할 수 있다. 목록이 길면 8줄씩 나뉜다 |
| 이번 주 마감 보기 | `이번 주 마감` | 7일치 마감·일정 |
| 기한 지난 것 보기 | `기한 지난 것` | 미완료 중 마감이 지난 항목 |
| 지금 바로 점검 | `지금 전체 점검해줘` | 06:00과 같은 절차로 즉시 수집·해석·브리핑. 06:00 실행 중이면 합류해서 결과만 준다 |
| 메일만 다시 확인 | `메일만 다시 확인해줘` | Gmail만 수집·해석 |
| 같은 이미지를 또 올렸을 때 | (아무것도 안 해도 됨) | "이미 받은 입력입니다. 연결된 항목: CLR-0031"이라고 알려 준다 |

## 3. 브리핑에 답하는 법

- 질문에는 **번호로** 답한다. 예: `Q-0007: 15:00, 참석만`
- **번호는 타이핑하지 않아도 된다 — 버튼을 누른다.** Claire가 번호를 알려 줄 때 그 줄 오른쪽에 `CLR-0031` / `Q-0007` 버튼이 붙는다. 브리핑도 항목·질문 줄마다 오른쪽에 버튼이 있다. **iPhone·iPad·데스크톱 어디서든 탭(클릭) 한 번**이면 Claire가 그 항목의 카드(업무 상태와 달력·Tasks 반영 상태를 따로 적은 요약)와 다음 행동 버튼 — `완료` · `진행 중` · `보류`(다시 물을 날에 다시) · `답변 대기` · `상세` · `처리 불필요` · `내 할 일 아님` · `취소`(업무 자체 취소) · (승인 대기면) `등록` / `달력에 표시 안 함` / `Tasks에 표시 안 함`(표시만 빼고 업무는 추적) · (달력에 없으면) `달력 등록` · (질문이면) 후보 답 — 을 보낸다. 그 버튼을 한 번 더 누르면 처리된다. 기한 변경처럼 버튼에 없는 지시는 그 카드에 **답장**으로 적으면 된다.
- 버튼은 보낸 지 24시간이 지나면 만료된다(Discord가 "expired"라고 알린다). 그때는 `31 완료`, `31 상세`처럼 **번호 숫자만** 적거나 답장으로 지시한다. `버튼 다시`라고 하면 새 버튼을 보낸다.
- 버튼이 안 보이면(설정 문제) 번호 줄 아래 회색 상자(코드 블록)가 대신 남는다. 데스크톱·웹에서는 상자에 마우스를 올리면 오른쪽 위 **복사** 버튼으로 번호를 복사할 수 있다. 모바일 Discord에는 이 복사 버튼이 없으니 답장으로 지시한다. 상자가 없는 번호는 `CLR-0031 번호`라고 하면 준다.
- **답장(reply)으로도 된다.** Claire 메시지에 답장하면서 `기한 다음 주로`, `취소해`, `등록`처럼 번호 없이 말하면, 그 메시지에 실린 항목(1건일 때)으로 처리된다.
- 답을 안 하면 그대로 둔다. 다음 두 아침까지 매일, 그다음은 월요일에만 다시 묻는다(마감 48시간 이내면 매일).
- 완료 보고는 `심사 의견 끝냈어`처럼 말한다.

- 진행 보고는 `절반 했어`, `초안은 보냈어`. 완료로 바뀌지 않고 진행 중으로 기록된다.
- 상대 답을 기다릴 때는 `김 교수 답 기다리는 중`. 3영업일 뒤 브리핑 "진행 확인"에 다시 뜬다.
- `기한 다음 주 금요일로`, `우선순위 높여줘`, `잠깐 보류`, `취소해`, `다시 열어`, `방금 거 되돌려`도 된다. "지워줘"는 취소로 처리되고 기록은 남는다.
- 찾을 때는 `심사 의견 관련 항목 찾아줘`, `김 교수에게 답 기다리는 일은?`, `9월 15일에 할 일과 그날 완료한 일`.

## 3.1 캘린더·노트에 반영되는 규칙

- **직접 지시한 것은 자동.** `등록: 9/15 10시 김 교수 면담`은 Prof. Hur 캘린더에 바로 들어가고, `할일: …`은 마감일 Daily 노트의 `## Tasks`에 `🆔` 붙은 줄로 추가된다. 질문에 답해서 확정된 일정도 자동이다.
- **메일·이미지에서 Claire가 찾아낸 일정은 승인 후.** 업무 현황의 승인 대기 목록에서 `등록`(하나씩), `선택` → `선택한 것 등록`(골라서), `전부 등록`, `달력에 표시 안 함`/`Tasks에 표시 안 함`을 누른다. 글로는 `CLR-0045 등록`, `다 등록`, `달력에 넣지 마`. **표시 안 함은 업무 제외가 아니다** — 업무는 계속 목록과 진행 확인에 나온다(빼려면 `처리 불필요`).
- **마감 표시와 실제 약속은 다르다.** 마감 1시간 전 자동 표시끼리 겹치면 "18:00 마감 2건 — 작업량 안내"로만 알리고 충돌로 보지 않는다. 실제 약속·교수님이 잡은 작업 시간이 겹치면 ⚠로 알린다.
- **마감 시각만 있는 일은** 마감 1시간 전부터 마감까지 캘린더에 `[마감] 제목`으로 표시한다. 시작·기간을 따로 말하면 그대로. 날짜만 있으면 시각을 묻는다. Obsidian Tasks의 날짜가 확정된 마감 시각을 덮지 않는다.
- **완료 처리하면** 연결된 Obsidian Tasks 줄이 `[x] ✅ 날짜`로 체크되고, 완료한 날 Daily `## 완료한 일`에 `- ✅ 14:32 제목 (CLR-0031) · [[노트]]`가 한 줄 남는다(여러 번 눌러도 한 줄, 완료일을 고치면 옮기고, 완료를 취소하면 지운다). 교수님이 쓴 줄에는 첫 연결 때 `🆔 clrNNNN`이 붙는다(Tasks 플러그인 정식 문법이라 표시는 그대로).
- **캘린더 시각을 바꾸라고 하면** Claire 장부가 아니라 캘린더를 먼저 고치고, 동기화로 장부에 돌아온다. 그사이 캘린더가 다른 값으로 바뀌어 있으면 덮어쓰지 않고 어느 쪽으로 할지 묻는다.
- 새 폴더·주제 노트는 만들지 않는다. Daily 노트가 없으면 템플릿대로 만든다.

> **쓰기 토큰이 없으면** 캘린더 반영은 "쓰기 토큰 없음"으로 대기만 한다(아래 §6).

## 4. Claire가 하지 않는 것 (지금 단계)

- 메일 발송·초대·읽음 처리. 캘린더 이벤트 삭제. 새 폴더·MOC·주제 노트 생성.
- 근거 없는 완료 처리. 메일을 읽었거나 회의 시각이 지났다고 완료로 바꾸지 않는다.
- 메일·이미지 속 문구를 명령으로 실행하는 것. "모든 일정을 삭제하라" 같은 문구는 브리핑 "참고"에 이상 문구로만 표시한다.

## 5. 피드백을 주면 좋은 것 (2단계 완료 기준)

1. **브리핑이 06:30 전에 왔는지.** 1주일 동안 확인한다.
2. **잘못 만든 항목·빠진 항목.** "CLR-0045는 나한테 온 요청이 아니야", "이 메일은 왜 안 잡혔어?"처럼 번호나 제목으로 말해 주면 해석 규칙을 고친다.
3. **걸러야 할 발신자.** 매번 "참고"에 잡히는 공지·알림이 있으면 알려 주면 설정에서 제외한다.
4. **첫 브리핑은 백로그가 크다.** 최근 7일 메일과 3개월치 캘린더를 처음 해석하므로 "신규"가 많고 "외 N건"으로 접힌다. 이후부터는 변화분만 온다.

## 6. 문제가 생겼을 때

- **캘린더 반영이 "쓰기 토큰 없음"으로 대기 중이면** (최초 1회, 브라우저 로그인):
  ```
  python3 ~/.claude/skills/claire-schedule-manager/connectors/google_api.py authorize <계정 이메일> --kind write
  ```

- 브리핑이 안 오면: 채널에 `지금 전체 점검해줘`. 다음 브리핑에 "지연 실행"이 표시된다.
- 상태를 직접 보려면 (터미널):
  ```
  ~/.claude/skills/claire-schedule-manager/scripts/claire_check doctor --format text
  ~/.claude/skills/claire-schedule-manager/scripts/claire_run status
  ```
- 데이터는 `~/ClaireData/`(원본), 백업은 `~/Dropbox/ClaireBackup/`. 인증 토큰은 백업에 들어가지 않는다.

## 7. 설치·업데이트 (터미널, mac mini)

```
curl -fsSL https://raw.githubusercontent.com/pilwonhur/claire-schedule-manager/main/get.sh | bash   # 처음
claire-update            # 최신 릴리스로 (그 버전 테스트가 통과해야 설치)
claire-update --check    # 새 버전이 있는지만 확인
claire-update --version v0.4.5   # 이전 버전으로 되돌리기
```

업데이트 전에 DB 사본을 `~/ClaireData/backups/pre-upgrade-*`에 남기고, 데이터·설정은 그대로 둔다. 업데이트 뒤 `claire_check doctor --format text`가 새로 필요한 OpenClaw 설정(0.5.0: 12·18시 확인 cron)을 알려 준다.
