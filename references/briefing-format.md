# 브리핑 형식 (PRD §8.2)

## 0.7.0 — 아침 보고는 짧은 브리핑 + 도구의 아침 보고 (이슈 2026-09-29)

전체 업무는 계속 추적하되 교수님께는 필요한 내용만 제한된 분량으로 전달한다.

1. **브리핑**(Claire 가 쓴다, 메시지 1개): 머리글(실행 시각·소스 상태) · 중요한 신규·변경 **최대 5줄**(번호 버튼) ·
   나머지는 `신규 12건 · 변경 4건 — 아래 보고의 각 구역에 반영` 한 줄 · 참고 한 줄(제외한 메일·신뢰도 낮은 항목·이상 문구).
   신규·변경을 다시 길게 나열하지 않는다. 질문·완료 건수·승인 대기·운영 점검은 쓰지 않는다(아침 보고 마지막 쪽에 있다).
2. **아침 보고**(`claire_buttons report`, 도구가 만든다): 오늘(달력 일정·달력 밖 오늘 마감) → 기한 지남 **한 쪽** → 진행 확인
   **최대 두 쪽** → 확인·상태 한 쪽(질문 최대 3 · Tasks 문서 위치 질문 · 완료 반영 N건 · 승인 대기·지난 일정·대기 건수 · 운영 요약 ·
   전체 보기 버튼). 빈 구역은 쪽을 만들지 않고 상태 쪽에 한 줄. SKILL §5.1.

```

**2. 오늘 마감 — 달력 밖 (1)**
  오늘 마감  명단 회신 (CLR-0103) · 중요 · 직접 요청                      [CLR-0103]
```
```

```
```
**5. 확인 필요 (2)**

- 키워드는 업무의 `short_label`(1~3단어, Claire 가 등록 때·`labels`로 적는다)이 없으면 제목 앞부분이다. 괄호 안 숫자는 짧은 번호다.
- 버튼으로 보인 업무만 "진행을 물어봄"으로 기록된다. 키워드로 줄인 업무는 다음 보고에 차례로 상세로 올라온다(돌려 가며 보이기).
- 지난 일정은 건수만(완료로 보지 않는다). 미래 정기·단발 일정은 기본 보고에 없다(전날·당일에 나온다). 전체는 `전체 목록`.
- 충돌 표기(R7): `⚠ 겹침`은 실제 약속·작업 예약·가족 일정끼리만. 마감 표시끼리 겹친 것은 `⏱ 18:00 마감 2건 — 작업량 안내`.

## 0.6.x — 업무 현황 (지금은 "전체 목록" 요청 때만)

`claire_buttons agenda`: 오늘 일정·마감 → 오늘 진행 확인 → 그 외 활성 업무 → 답변 대기·보류 → 승인 대기 → 반영·전달 점검.
활성 미완료 업무 전체가 번호 버튼과 함께 실린다. 앞으로의 정기 일정은 시리즈마다 한 줄. 0.7.0 부터 아침에는 보내지 않는다.

아래는 0.5.x 형식(참고용 — 0.7.0 에서는 머리글·신규·변경·참고 부분의 문체만 쓴다. 오늘 일정·우선 처리·진행 확인·확인 필요(질문)·
반영 상태는 아침 보고가 맡는다).

`claire_search review --run <id>`의 반환을 재료로 아래 형식을 만든다. 변화 없는 항목은 나열하지 않는다.

**승인 대기 목록은 요청 시** (0.7.0: 아침 보고에는 건수와 `승인 대기 보기` 버튼만, SKILL §5.1a). 예전에는 브리핑 직후 `claire_buttons approvals`를 따로 보냈다.
형식은 같다(`등록 안 함` 버튼 이름이 `달력에 표시 안 함`·`Tasks에 표시 안 함`으로 바뀌었다 — 외부 표시만 빼고 업무는 추적).
달력 등록 대기와 Tasks 등록 대기를 나눠 항목마다 제목·일시·업무 상태와 `등록`·`선택`·`등록 안 함`·`상세` 버튼,
끝에 `선택한 것 등록`·`전부 등록`이 붙는다. 지난 일정은 목록에서 빠지고 건수만 보인다(기록은 그대로).
브리핑 본문에는 건수만 쓰고 승인 대기 항목의 번호를 반복하지 않는다.

```
승인 대기 — 달력 2건 · Tasks 1건
**달력 등록 대기 (Google Calendar)**
CLR-0045 IROS 조직위 회의
9/15(화) 10:00–11:00 · 업무 할 일 · 참석 미정
  [CLR-0045 달력 등록] [CLR-0045 선택] [CLR-0045 등록 안 함] [CLR-0045 상세]

**상태 표기**: 항목 줄에는 필요할 때 `state_line`(`업무 할 일 · 달력 승인 대기 · 참석 미정`)을 붙여 업무 상태와
외부 반영 상태를 구분한다. "달력 등록됨"은 업무 완료가 아니다.

**번호 복사 블록 = 번호 버튼 자리** (SKILL §5): 항목·질문 줄 **바로 다음 줄**에 그 줄의 번호를 `` ```CLR-0012``` `` 한 줄 코드 블록으로 하나씩 붙인다. 이 본문을 `claire_buttons build --file briefing.md`로 변환해 message 도구로 보내면, 블록이 있던 줄이 "줄 + 오른쪽 `CLR-0012` 버튼"이 되어 iPhone·iPad에서도 탭 한 번으로 그 항목을 고를 수 있다(누르면 Claire가 항목 카드와 끝냈어·진행 중·보류·취소·등록 버튼을 보낸다). 버튼을 못 쓰면 블록이 그대로 남아 데스크톱의 "복사" 버튼으로 쓴다.

- 한 줄에 번호가 둘이면(회의 + 준비 항목) 블록 둘을 나온 순서대로. 첫 번호는 줄 오른쪽 버튼, 둘째는 그 아래 버튼 행이 된다.
- 같은 번호는 브리핑에서 **처음 나온 자리에만**. 우선 처리에 나온 신규 항목이 신규·변경에 또 나오면 두 번째는 생략한다.
- 부가 언급에는 붙이지 않는다: 괄호 안 `Q-0007 답변 대기`, 겹침 경고의 상대 항목(회의 번호 자체에는 붙인다), 반영 상태·참고 줄의 번호.
- 주말·"변화 없음" 브리핑처럼 번호가 없으면 자연히 없다. `claire_buttons build`가 Discord 한도(메시지당 컴포넌트 40개·4,000자)에 맞춰 여러 메시지로 나누므로 브리핑 파일은 하나로 쓴다. 나눠진 메시지는 머리글에 "(계속 2/2)"가 붙는다.

## 규칙

- 답변은 `Q-0007: 15:00, 참석만`처럼 번호로 하도록 형식이 유도한다. 질문 뒤에 후보(`options`)와 이유(`reason`)를 붙인다.
- `captured`(신뢰도 낮음)와 `suspicious`는 "참고" 줄에만, 한 번만.
- 주말(D7) 브리핑은 "확인 필요"와 반영 상태만. 변화가 없으면 "변화 없음" 한 줄. 업무 현황은 주말에도 전체를 보낸다
  (보통 중요도의 진행 확인 주기는 주말을 세지 않으므로 주말 2구역은 높음·전날·당일·기한 경과·재확인일 위주다).
- 수시 점검(`on_demand`)은 헤더를 `[점검 결과 HH:MM]`으로 바꾸고, 소스 지정 점검은 그 소스의 변화만 쓴다.
- 조회만 한 답변("오늘 남은 일")에는 `data_as_of`를 "데이터 기준 시각: 06:07"로 붙인다.
- 브리핑 본문을 파일로 저장한 뒤 `claire_run brief --run <id> --file`로 기록한다. `duplicate=true`면 보내지 않는다. 보낼 때는 `claire_buttons build --file … --record brief --briefing <id>`의 `messages[]`를 message 도구로 순서대로 보내고, 쪽마다 `claire_run deliver --id <delivery_id> --status sent|failed`, 최종 답변은 `NO_REPLY`. message 도구가 없으면 본문을 그대로 답하고 `--status sent --via reply`.
