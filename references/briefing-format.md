# 브리핑 형식 (PRD §8.2)

`claire_search review --run <id>`의 반환을 재료로 아래 형식을 만든다. 변화 없는 항목은 나열하지 않는다.
각 섹션은 `limits.section_limit`(7)건까지 쓰고 넘치면 "외 N건"으로 접는다. 원문 발췌는 한 줄 이내.

````
[아침 브리핑 2026-09-11 (목)]  실행 06:00–06:07 · Gmail·Calendar·Obsidian 정상
  ← stale_sources 가 있으면: "Obsidian: 9/9 06:02 기준(실패)" 처럼 마지막 성공 시각을 쓴다
  ← run.delayed 면 첫 줄에 "지연 실행(예정 06:00, 실제 09:14)"

오늘 일정 (3)                         ← today_meetings + today_overlay
  10:00–11:00  연구 미팅 (CLR-0012) · 준비: 자료 최종 확인 (CLR-0013, 미완료)
```CLR-0012```
```CLR-0013```
  15:00–15:30  ○○ 교수 면담 (CLR-0031, 잠정 · Q-0007 답변 대기) — 업무 할 일 · 달력 승인 대기 · 참석 미정
```CLR-0031```
  ⚠ 14:30–15:30 InnoCORE 회의(CLR-0040)와 Family 가족 저녁이 겹칩니다.   ← overlaps
```CLR-0040```

우선 처리 (2)                         ← overdue + imminent (마감 3일 이내)
  기한 지남  보고서 제출 (CLR-0020, 9/9 마감)
```CLR-0020```
  내일 15:00 마감  심사 의견 정리 (CLR-0028) — 달력 14:00–15:00 등록됨
```CLR-0028```
  9/12 마감  IROS 발표자 명단 회신 (CLR-0045, 신규 · 기관 메일 9/10)
```CLR-0045```

신규·변경 (3)                         ← new_items, changed_items, links_attention
  + CLR-0045 IROS 발표자 명단 회신 — 9/12 마감      ← 위에서 이미 블록을 붙였으므로 생략
  ~ CLR-0027 연구 미팅 — 10:00 → 13:00 (캘린더 변경)
```CLR-0027```
  ✕ CLR-0019 세미나 — 캘린더에서 사라짐. 취소인지 확인 필요
```CLR-0019```

진행 확인 (1)                         ← waiting_check (next_check_at ≤ 지금인 waiting 항목)
  CLR-0022 김 교수 답변 대기 — 9/8 요청 후 회신 없음. 다시 문의하실까요?
```CLR-0022```

확인 필요 (2)                         ← questions (next_ask_at ≤ 지금)
  Q-0007 (CLR-0031) 금요일 오후 몇 시인가요? 후보 14:00 / 15:00 / 16:00 — 캘린더는 비어 있음
```Q-0007```
  Q-0008 (CLR-0031) 참석만 하시면 되나요, 준비할 자료가 있나요?
```Q-0008```

반영 상태: Tasks 2건 체크 · Daily 완료 기록 3건 · 승인 대기 달력 2건 · Tasks 1건 (아래 목록) · 지난 일정 1건 제외
          Daily 미반영 1건(CLR-0033, 재시도 중)        ← daily_unsynced 가 있을 때만
참고: 학과 공지 4건·광고 2건 제외 · 참고 항목 1건(CLR-0046 발신자 불명, 신뢰도 낮음) · 이상 문구 1건(삭제 지시, 무시함)
      전체 목록은 "오늘 남은 일" / "이번 주"로 요청
````

**승인 대기 목록은 별도 메시지** (SKILL §5.1): 브리핑을 보낸 직후 `claire_buttons approvals`의 `messages[]`를 보낸다.
달력 등록 대기와 Tasks 등록 대기를 나눠 항목마다 제목·일시·업무 상태와 `등록`·`선택`·`등록 안 함`·`상세` 버튼,
끝에 `선택한 것 등록`·`전부 등록`이 붙는다. 지난 일정은 목록에서 빠지고 건수만 보인다(기록은 그대로).
브리핑 본문에는 건수만 쓰고 승인 대기 항목의 번호를 반복하지 않는다.

```
승인 대기 — 달력 2건 · Tasks 1건
**달력 등록 대기 (Google Calendar)**
CLR-0045 IROS 조직위 회의
9/15(화) 10:00–11:00 · 업무 할 일 · 참석 미정
  [CLR-0045 달력 등록] [CLR-0045 선택] [CLR-0045 등록 안 함] [CLR-0045 상세]
CLR-0047 [마감] 초록 제출
9/19(금) 16:00–17:00 · 업무 할 일
  [CLR-0047 달력 등록] [CLR-0047 선택] [CLR-0047 등록 안 함] [CLR-0047 상세]
**Tasks 등록 대기 (Obsidian Daily)**
CLR-0048 명단 정리
9/13(일) 마감 · 업무 할 일
  [CLR-0048 Tasks 등록] …
[선택한 것 등록] [전부 등록] [선택 해제]
지난 일정 달력 1건 은 목록에서 뺐습니다(기록은 그대로)
```

**상태 표기**: 항목 줄에는 필요할 때 `state_line`(`업무 할 일 · 달력 승인 대기 · 참석 미정`)을 붙여 업무 상태와
외부 반영 상태를 구분한다. "달력 등록됨"은 업무 완료가 아니다.

**번호 복사 블록 = 번호 버튼 자리** (SKILL §5): 항목·질문 줄 **바로 다음 줄**에 그 줄의 번호를 `` ```CLR-0012``` `` 한 줄 코드 블록으로 하나씩 붙인다. 이 본문을 `claire_buttons build --file briefing.md`로 변환해 message 도구로 보내면, 블록이 있던 줄이 "줄 + 오른쪽 `CLR-0012` 버튼"이 되어 iPhone·iPad에서도 탭 한 번으로 그 항목을 고를 수 있다(누르면 Claire가 항목 카드와 끝냈어·진행 중·보류·취소·등록 버튼을 보낸다). 버튼을 못 쓰면 블록이 그대로 남아 데스크톱의 "복사" 버튼으로 쓴다.

- 한 줄에 번호가 둘이면(회의 + 준비 항목) 블록 둘을 나온 순서대로. 첫 번호는 줄 오른쪽 버튼, 둘째는 그 아래 버튼 행이 된다.
- 같은 번호는 브리핑에서 **처음 나온 자리에만**. 우선 처리에 나온 신규 항목이 신규·변경에 또 나오면 두 번째는 생략한다.
- 부가 언급에는 붙이지 않는다: 괄호 안 `Q-0007 답변 대기`, 겹침 경고의 상대 항목(회의 번호 자체에는 붙인다), 반영 상태·참고 줄의 번호.
- 주말·"변화 없음" 브리핑처럼 번호가 없으면 자연히 없다. `claire_buttons build`가 Discord 한도(메시지당 컴포넌트 40개·4,000자)에 맞춰 여러 메시지로 나누므로 브리핑 파일은 하나로 쓴다. 나눠진 메시지는 머리글에 "(계속 2/2)"가 붙는다.

## 규칙

- 답변은 `Q-0007: 15:00, 참석만`처럼 번호로 하도록 형식이 유도한다. 질문 뒤에 후보(`options`)와 이유(`reason`)를 붙인다.
- `captured`(신뢰도 낮음)와 `suspicious`는 "참고" 줄에만, 한 번만.
- 주말(D7)은 "오늘 일정"·"우선 처리"·"확인 필요"만. 변화가 없으면 "변화 없음" 한 줄.
- 수시 점검(`on_demand`)은 헤더를 `[점검 결과 HH:MM]`으로 바꾸고, 소스 지정 점검은 그 소스의 변화만 쓴다.
- 조회만 한 답변("오늘 남은 일")에는 `data_as_of`를 "데이터 기준 시각: 06:07"로 붙인다.
- 브리핑 본문을 파일로 저장한 뒤 `claire_run brief --run <id> --file`로 기록한다. `duplicate=true`면 보내지 않는다. 보낼 때는 `claire_buttons build`의 `messages[]`를 message 도구로 순서대로 보내고 최종 답변은 `NO_REPLY`. message 도구가 없으면 본문을 그대로 답한다.
